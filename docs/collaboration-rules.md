# 协作规则

这个文件记录用户和 Codex 一起学习、开发这个项目时的长期约定。

如果以后换电脑、重新打开项目、或者上下文丢失，先阅读这个文件。

## 用户目标

用户想通过课程项目和开源案例学习 AI 应用开发，并沉淀成适合简历展示的真实项目。

重要偏好：不要把提示词、学习资料、课程笔记或职业规划数据库当作主项目。主项目必须像一个可以运行、可以测试、可以演示 API 或界面的工程作品。

目标岗位方向：

- AI 应用工程师
- LLM 应用开发
- RAG / Agent / 数据分析助手相关岗位

## 学习方式

- 不要一下子把完整项目全部做完。
- 用任务卡的方式一步一步引导。
- 每一步只完成一个明确的小目标。
- 用户代码能力目前偏基础，需要解释“为什么这样做”，而不是只给答案。
- 优先让用户理解流程，再逐步加功能。
- 遇到代码时，要鼓励用户先尝试，再根据报错和结果调整。

## 项目方向

优先选择简历价值高、学习曲线适中的项目：

- LearningHub
- PDF 对话 / 基础 RAG
- 数据分析 Agent
- Web 研究 Agent
- Agent 化 RAG

当前旗舰项目是 `projects/02-rag-fastapi-service`。它已从纯 RAG FastAPI 服务升级为参考 `RMA-MUN/RAGNotebook` 产品方向的 `LearningHub`。项目采用 `embeddinggemma:300m` 检索和 `qwen2.5:3b` 来源约束生成，定位为用户自己能讲清楚的轻量版 Notebook RAG，不直接照搬课程代码或完整开源项目。

暂时避免一开始就做依赖复杂、成本高、难调试的项目。

## GitHub 与同步规则

- 项目要持续同步到 GitHub。
- 每完成一个清晰的小阶段，就 commit 并 push。
- 保持 README、运行命令、接口说明、测试和项目取舍清楚。
- 换电脑时，通过 GitHub clone 仓库继续。
- 不要提交 `.env`、API key、私人文件或大体积临时文件。

## 外部资料与浏览器约束

- 遇到不了解、没有现成依据或不确定的内容，先查 GitHub 上的参考项目、官方文档或 issue，再决定是否实现。
- 禁用内置浏览器；需要网页时只能使用外置浏览器。任务无法执行时也不能改用内置浏览器。
- 用户提醒过的长期偏好、项目约定和工具限制，及时写入本文件或其他项目记忆文档，避免换电脑或上下文变化后遗忘。

## 客户界面文案规则

- 面向客户的页面只展示产品功能、数据状态、操作结果和必要的安全提示。
- 不展示“当前阶段”“下一阶段”“开发中”“待补充”“演示截图”等内部开发过程信息。
- 不把项目计划、失败案例记录、简历准备和 Codex 协作内容放进产品工作台。
- 新增功能必须先检查页面文案是否仍然符合客户使用场景；技术细节只在确实帮助用户完成操作时展示。
- DataPilot 的练习数据中心提供 10 组中文合成数据，每组同时支持 CSV 和 XLSX，用于查看、练习和验收。

## 排错规则

遇到跑不通时，不要急着大改代码。

先按 `docs/troubleshooting-rules.md` 排查：

- 读完整报错。
- 判断问题类型。
- 查本地项目文档。
- 查官方文档。
- 查 GitHub issues、discussions、pull requests、release notes。
- 找到原因后只做最小必要修改。
- 验证成功后记录问题和解决方法。

## 记忆规则

用户以后说过的重要注意事项、偏好、项目约定、排错习惯，都要记录到仓库文档中。

这样即使换电脑或上下文变化，也能通过 GitHub 保留项目记忆。
