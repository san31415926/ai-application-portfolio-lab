# Collaboration Rules

这个文件记录用户和 Codex 一起学习、开发这个项目时的长期约定。

如果以后换电脑、重新打开项目、或者上下文丢失，先阅读这个文件。

## User Goal

用户想通过 `awesome-llm-apps` 里的案例学习 AI 应用开发，并沉淀成适合简历展示的项目。

目标岗位方向：

- AI 应用工程师
- LLM 应用开发
- RAG / Agent / 数据分析助手相关岗位

## Learning Style

- 不要一下子把完整项目全部做完。
- 用任务卡的方式一步一步引导。
- 每一步只完成一个明确的小目标。
- 用户代码能力目前偏基础，需要解释“为什么这样做”，而不是只给答案。
- 优先让用户理解流程，再逐步加功能。
- 遇到代码时，要鼓励用户先尝试，再根据报错和结果调整。

## Project Direction

优先选择简历价值高、学习曲线适中的项目：

- Chat with PDF
- Basic RAG
- AI Job Description Knowledge Base
- Data Analysis Agent
- Web Research Agent
- Agentic RAG

暂时避免一开始就做依赖复杂、成本高、难调试的项目。

## GitHub And Sync Rules

- 项目要持续同步到 GitHub。
- 每完成一个清晰的小阶段，就 commit 并 push。
- 保持 README、任务卡、学习笔记清楚。
- 换电脑时，通过 GitHub clone 仓库继续。
- 不要提交 `.env`、API key、私人文件或大体积临时文件。

## Troubleshooting Rule

遇到跑不通时，不要急着大改代码。

先按 `docs/troubleshooting-rules.md` 排查：

- 读完整报错。
- 判断问题类型。
- 查本地项目文档。
- 查官方文档。
- 查 GitHub issues、discussions、pull requests、release notes。
- 找到原因后只做最小必要修改。
- 验证成功后记录问题和解决方法。

## Memory Rule

用户以后说过的重要注意事项、偏好、项目约定、排错习惯，都要记录到仓库文档中。

这样即使换电脑或上下文变化，也能通过 GitHub 保留项目记忆。
