# LearningHub 项目总结

## 一句话定位

LearningHub 是一个参考 `RMA-MUN/RAGNotebook` 产品方向重新实现的中文本地 RAG 学习知识库与 Notebook 工作台，用于展示文档入库、切片、向量检索、来源约束回答、拒答、降级和笔记关联能力。

## 项目故事

### 背景

普通搜索只能返回关键词匹配结果，用户还需要自己打开文档、筛选上下文和整理答案。LearningHub 将中文教程资料变成可检索知识库，并在回答中保留来源片段，降低模型脱离资料自由发挥的风险。

### 输入

- 用户上传的 `.txt`、`.md`、`.pdf` 文件
- 内置 227 份中文学习教程，自动生成 205 条可搜索、可编辑、可复习的学习笔记，覆盖生活百科、做菜、C 语言、Python、FastAPI、前端、Excel、SQL、Git、Linux、数据分析和 RAG 等主题
- 用户的问题、学习笔记和笔记标签

### 处理链路

```text
文档上传
  -> 文本解析与清洗
  -> 文本切分
  -> Ollama embeddinggemma:300m 生成向量
  -> 余弦相似度检索
  -> 低相关度拒答
  -> 用户选择的 Ollama 聊天模型基于来源生成回答
  -> 返回回答、来源和模型信息
```

Ollama 不可用时，检索层会退回本地 sparse embedding；生成模型不可用时，回答层会退回基于来源片段的提取式回答。这样测试和演示不依赖云端 API key。

## 当前功能

- FastAPI REST API 和自动生成的 OpenAPI 文档
- `.txt`、`.md`、`.pdf` 文档上传、解析、切片和批量索引
- Ollama 本地 embedding 检索与 sparse fallback
- 根据检索结果生成带来源标记的中文回答
- 低置信度拒答，拒绝回答知识库无法支撑的问题
- `/api/v1/models` 发现本机聊天模型，页面下拉选择本次回答模型
- Notebook 笔记 CRUD、搜索、关联来源、写作辅助和回顾提醒
- 10 项 API 测试覆盖健康检查、入库、查询、拒答、上传、教程笔记批量导入、模型接口、本地写作辅助和流式问答

## 当前限制

- 向量索引和笔记暂存在内存中，服务重启后需要重新加载
- 尚未接入 Chroma 持久化和完整检索评估集
- 写作辅助默认调用本地 `qwen2.5:3b`，模型不可用时退回确定性逻辑；当前仍不是流式 LLM Agent
- Qwen3 在当前 Ollama 版本下可能返回额外思考内容，因此默认使用 `qwen2.5:3b`
- 暂无用户登录、会话历史、部署地址和多用户隔离

## 简历项目名称

**LearningHub：本地 RAG 学习知识库**

## 简历描述

- 基于 FastAPI 设计中文 RAG 知识库，支持 TXT、Markdown、PDF 文档上传、文本切分、Ollama embedding 检索和来源片段返回。
- 接入 Ollama 本地生成模型，增加 `/api/v1/models` 模型发现接口和页面模型选择器，支持按请求切换聊天模型且不改变服务默认配置。
- 设计低相关度拒答、生成失败降级和来源约束提示，避免将知识库外问题交给模型随意回答。
- 实现 Notebook 笔记管理、相关来源检索、示例教程库、本地 Qwen 写作辅助、SSE 流式问答和 10 项 API 测试，形成可运行、可演示、可解释的 AI 应用原型。

## 面试时的 60 秒讲法

我做的是一个中文学习知识库和 Notebook 工作台。用户可以上传 Markdown、TXT 或 PDF，系统先解析并切成多个片段，再用 Ollama 的 embedding 模型把片段和问题转换成向量，通过相似度检索出相关来源。如果相关度低于阈值，系统会直接拒答，不调用生成模型；如果命中，就把有限数量的来源片段交给本地聊天模型生成中文回答，并返回来源文件和切片信息。页面还可以发现本机已安装的聊天模型，用户按每次请求选择模型。为了保证项目在没有 Ollama 或模型异常时仍能演示，我保留了 sparse 检索和提取式回答两级降级方案。当前版本的主要限制是向量和笔记仍在内存中，下一步会升级 Chroma 和 SQLite。
